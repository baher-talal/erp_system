# طلال — نظام إدارة الشركة (ERP)

نظام ويب عربي/إنجليزي لإدارة العمليات اليومية للشركة. يحفظ البيانات في قاعدة بيانات MySQL، ويتطلب تسجيل الدخول، ويدعم صلاحيات مفصلة لكل مستخدم. الواجهة مبنية باستخدام Blade وHTML وCSS وJavaScript عادي؛ لا تحتاج إلى حزمة JavaScript أو إلى خادم Node لتشغيلها.

> **مهم قبل النشر:** هذا التطبيق مبني على Laravel 7 ومهيأ للعمل مع بيئة PHP قديمة (تم اختباره سابقاً على PHP 7.3.9). Laravel 7 وPHP 7.3 إصدارات منتهية الدعم الأمني. لا تعرّض نسخة قديمة للإنترنت قبل ترقية الإطار وPHP ومراجعة التبعيات والاستضافة. نفّذ النسخ الاحتياطي والترقية على بيئة تجريبية أولاً.

## محتويات النظام

| الوحدة | ما تنفذه |
|---|---|
| لوحة المعلومات | أعداد الموظفين والمشاريع والمهام، المشاريع والمهام الأخيرة، الحضور اليومي، ومبلغ المدفوعات المحصلة هذا الشهر للمدير. |
| الموظفون والأقسام | سجل الموظف وحسابه ودوره وبيانات الوظيفة والقسم؛ ربط الموظف بقسم فعلي، وتحديد مدير للقسم. المدير يستطيع إنشاء الحسابات وتعديلها وإعادة تعيين كلمات المرور وإيقاف الحسابات. |
| المهام | إنشاء وتعديل وبحث وتصفية المهام، تعيين مسؤول، تحديد الأولوية والحالة، وربط المهمة بمشروع. |
| العملاء والمشاريع | حفظ معلومات العميل، إنشاء مشروع مرتبط بعميل، وتسجيل التقدم والتواريخ والمبالغ. |
| المدفوعات | تسجيل الفواتير والمبالغ والتواريخ وطريقة الدفع وحالة التحصيل. |
| الرواتب | إنشاء سجل راتب لموظف وفترة شهرية، وإدخال الراتب الأساسي والبدلات والاستقطاعات. يحسب الخادم صافي الراتب: الأساسي + البدلات - الاستقطاعات، ويرفض الاستقطاعات التي تتجاوز المستحق. |
| الملفات | رفع ملفات المستندات والصور الشائعة (حتى 10 ميغابايت) إلى التخزين المحلي الخاص؛ التنزيل يتطلب جلسة دخول ولا يُكشف مسار التخزين في استجابة القائمة. |
| الحضور والانصراف | يسجل الموظف حضوره وانصرافه لنفس حسابه فقط؛ لا يعتمد الخادم على اسم يرسله المتصفح. الموظف يرى سجلاته، والمدير يرى سجل الحضور العام. |
| التقويم | تسجيل المواعيد وتواريخها ومواقعها أو روابط الاجتماعات والحاضرين. |
| المخزون | تعريف الصنف ورمزه ووحدته وكميته وحد إعادة الطلب وفئته؛ تسوية الوارد والصادر تسجل حركة وسببها ومن نفذها، ولا تسمح بأن يصبح الرصيد سالباً. |
| المحادثات | رسائل داخلية مشتركة بين مستخدمي مساحة العمل، مع اسم المرسل؛ تتحدث القائمة كل خمس ثوانٍ أثناء فتحها. |
| قائمة شخصية | مهام خاصة بالحساب الحالي؛ لا يستطيع مستخدم آخر قراءتها أو تعديلها أو حذفها. |
| التقارير | أعداد السجلات حسب الوحدة، المهام المفتوحة والمكتملة، المدفوعات المستلمة والمستحقة، الرواتب المدفوعة والمستحقة، حضور اليوم، والأصناف عند حد إعادة الطلب. متاحة للمدير، ويمكنه منح صلاحية العرض لمستخدمين آخرين. |

تدعم القوائم البحث والحالة وترقيم الصفحات. الواجهة تدعم العربية RTL والإنجليزية LTR، والمظهر الفاتح والداكن. تفضيل المظهر محفوظ محلياً في المتصفح.

## الأدوار والصلاحيات

- **مدير النظام (`admin`):** صلاحية كاملة، بما فيها إنشاء حسابات الموظفين وتعديلها وإدارة صلاحياتهم.
- **مدير (`manager`) وموظف (`employee`):** صلاحيات كل حساب تُضبط بشكل مستقل من شاشة حساب الموظف؛ لا يمنح الدور وحده إذناً لتجاوز مصفوفة الصلاحيات.
- لكل وحدة يحدد المدير صلاحيات **العرض** و**الإضافة والتعديل** و**الحذف**. التقارير للعرض فقط. يمكن تفويض المدفوعات والرواتب صراحةً، وتظل غير متاحة افتراضياً.
- تُفرض الصلاحيات على الخادم لجميع مسارات القراءة والكتابة والحذف ورفع/تنزيل الملفات وتسويات المخزون وتسجيل الحضور، ولا يقتصر الأمر على إخفاء عناصر القائمة. كما تُرشّح بيانات لوحة المعلومات والتقارير وفق صلاحيات المستخدم، حتى لا تكشف بيانات وحدة غير مسموح بها.
- تبقى إدارة حسابات المستخدمين نفسها محصورة بمدير النظام. يحتفظ المستخدم بصلاحياته المسجلة في جدول `users`، ويُخزّن ملف الموظف نسخة للعرض الإداري فقط. تُعرّف الوحدات والإجراءات والقيم الافتراضية مركزياً في `config/erp.php`.
- المستخدمون القدامى الذين ليس لديهم مصفوفة صريحة يحتفظون بصلاحيات التشغيل الافتراضية؛ الحسابات الجديدة تحفظ المصفوفة التي يختارها المدير.

لا يُسمح بتسجيل مدير أول إلا مرة واحدة. بعد تهيئة النظام، ينشئ المدير حسابات الموظفين والمديرين من قسم الموظفين. يمكن تعديل الحساب المرتبط بملف الموظف أو إيقافه؛ الحساب الموقوف لا يستطيع تسجيل الدخول، والجلسات التي تستخدمه تُنهى عند طلب محمي لاحق.

عند ترقية قاعدة بيانات قديمة تحتوي مستخدمين قبل إضافة الأدوار، يعيّن ترحيل الأدوار أقدم مستخدم بحسب رقم `id` مديراً للنظام ويعيّن بقية المستخدمين موظفين. راجع هذه الحسابات قبل تشغيل الترحيل على قاعدة قائمة.

## الأدوات والتقنيات المستخدمة

### الخادم

- **PHP** مع **Laravel 7**: التوجيه، المصادقة والجلسات، التحقق من المدخلات، الصلاحيات، التخزين، والاستجابات.
- **Eloquent ORM**: قراءة السجلات وربطها بمستخدم الإنشاء والمسؤول.
- **MySQL / MariaDB**: قاعدة بيانات التشغيل الموصى بها؛ اتصالها يضبط من ملف `.env`.
- **SQLite داخل الذاكرة**: قاعدة معزولة للاختبارات، فلا تعدل اختبارات الميزات قاعدة التطوير.
- **Composer**: تثبيت حزم PHP المحددة في `composer.json` و`composer.lock`.

### المتصفح

- **Blade** لتوليد صفحات الدخول والإعداد ولوحة العمل.
- **HTML وCSS وJavaScript عادي (Vanilla JS)** للواجهات والنماذج والتفاعلات.
- ملفات الترجمة منفصلة حسب اللغة: `resources/lang/ar/ui.php` للنصوص العربية و`resources/lang/en/ui.php` للنصوص الإنجليزية؛ تستخدم الواجهة مفاتيح ترجمة بدلاً من تضمين نسختين من النص داخل عناصر HTML.
- **Fetch API وJSON** للاتصال بمسارات Laravel؛ و**CSRF token** لطلبات التعديل.
- لا يعتمد تشغيل واجهة ERP الحالية على React أو Vue أو Bootstrap أو jQuery أو مكتبة واجهة خارجية.
- إعدادات Laravel Mix وملفات JavaScript/Sass الافتراضية غير مطلوبة بعد إزالة الأصول غير المستخدمة؛ لذلك لا يلزم `npm install` لتشغيل التطبيق.

## متطلبات التشغيل

- PHP بإصدار يطابق قيود `composer.json` وإصدار Laravel المستخدم. البيئة التي جرى اختبارها سابقاً هي PHP 7.3.9، لكن يوصى بترقية المشروع قبل الاعتماد الإنتاجي.
- امتدادات PHP التي يحتاجها Laravel وقاعدة البيانات، ومنها `OpenSSL`, `PDO`, `pdo_mysql`, `Mbstring`, `Tokenizer`, `XML`, `Ctype`, `JSON`, و`Fileinfo`.
- Composer 2، وخادم MySQL أو MariaDB.
- Apache ضمن XAMPP أو خادم ويب آخر يشير جذر الموقع إلى مجلد `public`.
- مجلدا `storage` و`bootstrap/cache` قابلان للكتابة من مستخدم PHP.
- اضبط `upload_max_filesize` و`post_max_size` في PHP بما يتجاوز حد الملف (10 ميغابايت) قليلاً.

## الإعداد على Windows / XAMPP

1. أنشئ قاعدة MySQL فارغة من phpMyAdmin، مثلاً `erp_system`.
2. انسخ `.env.example` إلى `.env` إذا لم يكن موجوداً، ثم اضبط:

   ```dotenv
   APP_NAME="Talal ERP"
   APP_ENV=local
   APP_KEY=
   APP_DEBUG=true
   APP_URL=http://localhost
   APP_TIMEZONE=Asia/Riyadh

   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=erp_system
   DB_USERNAME=root
   DB_PASSWORD=

   FILESYSTEM_DRIVER=local
   SESSION_DRIVER=file
   ```

   غيّر `APP_TIMEZONE` إلى المنطقة الزمنية الفعلية للشركة. استخدم كلمة مرور قاعدة البيانات المناسبة لبيئتك ولا تضعها في ملفات عامة أو مستودع.

3. من مجلد المشروع ثبّت تبعيات PHP عند عدم وجود `vendor` أو بعد استنساخ المشروع:

   ```powershell
   composer install --no-dev --optimize-autoloader
   ```

   ولبيئة التطوير والاختبار استخدم `composer install` من دون `--no-dev`.

4. أنشئ مفتاح التطبيق **لأول تثبيت فقط**:

   ```powershell
   php artisan key:generate
   ```

   لا تغيّر المفتاح بعد بدء الاستخدام؛ تغييره يبطل الجلسات والبيانات المشفرة.

5. أنشئ الجداول:

   ```powershell
   php artisan migrate
   ```

   في بيئة الإنتاج استخدم `php artisan migrate --force` بعد أخذ نسخة احتياطية ومراجعة ملفات الترحيل.

6. في Apache/XAMPP اجعل **DocumentRoot** يشير إلى مجلد `public` داخل المشروع، لا إلى جذر المشروع؛ فهذا يمنع تقديم ملفات `.env` وملفات التطبيق مباشرة عبر الويب. للتطوير فقط يمكن التشغيل بـ:

   ```powershell
   php artisan serve --host=127.0.0.1 --port=8000
   ```

7. افتح `http://localhost/setup` (أو عنوان الخادم) وأنشئ حساب المدير الأول بكلمة مرور لا تقل عن 10 أحرف ولا تزيد على 72 بايت. بعدها أنشئ الحسابات من **الموظفون**.

8. في الإنتاج:
   - اجعل `APP_ENV=production` و`APP_DEBUG=false`.
   - استخدم HTTPS وكلمة مرور قاعدة بيانات محدودة الصلاحية.
   - امنع الوصول العام إلى `.env`, `storage`, `vendor` وجذر المشروع.
   - احتفظ بنسخ احتياطية متكررة لقاعدة البيانات ومجلد `storage/app/erp-files`.
   - لا تشغّل `migrate:fresh` على بيانات حقيقية؛ هذا الأمر يحذف الجداول والبيانات.

## قاعدة البيانات وسير البيانات

- جدول `users` يحفظ بيانات الدخول والدور وحالة الحساب.
- جدول `erp_records` يحفظ سجلات الوحدات. الحقول المشتركة هي الوحدة والعنوان والوصف والحالة والمبلغ والتاريخ والمسؤول ومنشئ السجل؛ أما التفاصيل الخاصة بالوحدة فتحفظ في حقل JSON باسم `metadata`.
- جدول `workspace_settings` يحفظ حالة الإعداد الأولي لمرة واحدة.
- ملفات الرفع في القرص `local` تحت `storage/app/erp-files`، وهي خارج `public`.
- العلاقات المهمة داخل `metadata` تُتحقق من وجود الهدف في الوحدة المناسبة، مثل المشروع والعميل، المهمة والمشروع، الموظف والقسم، الراتب والموظف.
- لا يُسمح بحذف قسم أو عميل أو مشروع أو ملف موظف مرتبط بسجلات أخرى؛ افصل العلاقات أولاً لتجنب سجلات يتيمة.
- البحث والصفحات تنفذ من الخادم، والصفحة تعرض حتى 50 سجلاً في كل مرة.
- استخدم الترحيلات لإضافة تغييرات مخطط البيانات، ولا تعدل قاعدة التشغيل يدوياً دون ترحيل موثق.

## مسارات التشغيل المهمة

| المسار | الغرض |
|---|---|
| `GET /` | يحول المستخدم لأول إعداد أو تسجيل الدخول أو لوحة العمل بحسب حالة النظام والجلسة. |
| `GET, POST /setup` | إنشاء مدير النظام الأول مرة واحدة. |
| `GET, POST /login` و`POST /logout` | تسجيل الدخول والخروج. محاولات الدخول والإعداد محدودة المعدل. |
| `GET /workspace/dashboard` | بيانات لوحة المعلومات. |
| `GET /workspace/{module}` | قائمة وحدة مع البحث والحالة والصفحة. |
| `POST /workspace/{module}` | إنشاء سجل تشغيلي حسب صلاحية الوحدة. |
| `PUT, DELETE /workspace/{module}/{id}` | تعديل السجل أو حذفه وفق الدور وملكية السجل. |
| `POST /workspace/employees/account` و`PUT /workspace/employees/{id}/account` | إنشاء الحساب المرتبط بملف الموظف وتحديثه. |
| `POST /workspace/attendance/clock` | تسجيل حضور أو انصراف الحساب المسجل فقط. |
| `POST /workspace/inventory/{id}/adjust` | إدخال أو صرف مخزون مع سجل حركة. |
| `POST /workspace/files/upload` و`GET /workspace/files/{id}/download` | رفع ملف خاص وتنزيله بعد المصادقة. |
| `GET /workspace/reports` | ملخص التقارير لمن يملك صلاحية عرض التقارير. |

أسماء الوحدات البرمجية: `employees`, `departments`, `tasks`, `projects`, `clients`, `payments`, `files`, `chat`, `attendance`, `payroll`, `calendar`, `inventory`, `personal_tasks`.

## الاختبارات والفحوصات

الاختبارات تستخدم SQLite في الذاكرة:

```powershell
php artisan test
```

تشمل اختبارات الميزات الإعداد الأولي والمصادقة، صلاحيات الحسابات، ربط الموظف بالقسم والمشروع بالعميل والمهمة بالمسؤول، خصوصية الحضور والمهام الشخصية، حساب صافي الراتب، حركة المخزون، ترقيم الصفحات، والرفع والتنزيل الخاص للملفات.

فحوصات مفيدة عند تغيير الكود:

```powershell
php -l app\Http\Controllers\ErpController.php
php artisan route:list
php artisan migrate:status
php artisan view:cache
```

امسح القوالب المخبأة بعد تعديل إعدادات العرض عند الحاجة:

```powershell
php artisan view:clear
```

## حدود النسخة الحالية وما ليس مفعّلاً

- المحادثة تُحدّث باستطلاع دوري كل 5 ثوانٍ، وليست بثاً فورياً عبر WebSocket.
- الرواتب تسجل الاستحقاق وصافي الراتب والبدلات والاستقطاعات، لكنها لا تطبق ضرائب أو تأمينات أو قوانين رواتب محلية، ولا تولّد كشوفاً محاسبية قانونية.
- المدفوعات سجلات داخلية فقط؛ لا يوجد ربط ببوابة دفع أو بنك أو مزود فواتير إلكترونية.
- الملفات محفوظة على القرص المحلي؛ المشاركة متاحة للمستخدمين المسجلين المصرح لهم، وليست صلاحيات مشاركة منفصلة لكل ملف.
- الحضور يثبت هوية الحساب ووقت الخادم، ولا يستخدم تحديد موقع أو جهاز بصمة أو قواعد مناوبات.
- دورا المدير والموظف لا يضيفان صلاحيات تلقائية؛ يحدد المدير العام صلاحيات كل حساب على حدة. المدير العام يملك صلاحية كاملة دائماً، ويمكنه منح صلاحية عرض البيانات المالية لمستخدمين آخرين.
- لا يوجد إرسال بريد دعوة أو إعادة تعيين كلمة مرور مهيأ، ولا مصادقة متعددة العوامل.
- مخطط ERP يستخدم جدول سجلات مشتركاً مع `metadata` مرن؛ هذا يقلل تعقيد النسخة الحالية لكنه ليس بديلاً عن تصميم محاسبي/موارد بشرية مطبّع ومتكامل على مستوى مؤسسة كبيرة.

## أهم الملفات

- `routes/web.php`: مسارات الدخول والوحدات.
- `app/Http/Controllers/AuthController.php`: الدخول والإعداد الأولي.
- `app/Http/Controllers/ErpController.php`: القراءة والكتابة والتحقق والصلاحيات والتقارير والحضور والمخزون والملفات.
- `app/ErpRecord.php`, `app/User.php`: نماذج البيانات والعلاقات.
- `database/migrations`: مخطط قاعدة البيانات والأدوار وحالة الإعداد وحالة الحساب.
- `resources/views/welcome.blade.php`: لوحة العمل والنماذج والتفاعلات العربية/الإنجليزية.
- `resources/views/auth.blade.php`: صفحات الدخول والإعداد.
- `tests/Feature/ErpWorkflowTest.php`: اختبارات سير العمل والصلاحيات.
